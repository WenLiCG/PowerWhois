### 为什么43使用QA harness

固定接口的 `lookuper.Whois`（`src/backend/lookup/lookuper/lookuper.go:114`）对 .com 优先 RDAP；`whoislib.WhoisSupportedTlds` 未提供 COM，亦无对外目标服务器覆盖参数。为遵守“不查.cn/CNNIC”同时检查 google.com 的43通路，本轮用 Go `-overlay` 替换 QA 编译视图中的 main.go，在额外 init 中清空 RDAP 支持列表，加入 COM→whois.verisign-grs.com 路由。首版暴露 COM 无解析器；修正版仅再把既有 `.co` 正则解析规则映射给 COM。未改候选文件、拨号器、超时、认证、错误分类、配置或 WebSocket 实现。差异可审计于 `main-whois43-first.go`、`main-whois43.go` 与 `overlay43.json`。

## 3. 环境、隔离与方法

- 共享 box Linux/amd64，Go1.27.3；构建环境 `GOPROXY=off GOSUMDB=off GOEXPERIMENT=nojsonv2 GOFLAGS=-ldflags=-checklinkname=0 GOCACHE=/tmp/qa-pw7d-85832335-gocache`。
- box 实际默认时区呈 CST（+08:00），因此本报告显式使用 America/Los_Angeles 转换，不直接照抄日志墙上时间。应用部分库会自行记录PRC时间，原始日志保留其偏移。
- 每例独立 HOME/缓存、假管理员/JWT、独立0600 config；本地 miniredis 子进程。原生 app 固定监听 `:8080`，不能改端口，本轮开始确认无监听，仅以127.0.0.1访问，不转发/发布该端口；未更改监听实现。不是容器/网络命名空间隔离，不能声称只绑定loopback。
- 本地TLS RDAP与WHOIS桩均监听127.0.0.1随机端口；SOCKS接受FQDN目的地址，受控转给本地目标。RDAP的本地新鲜 `.openrdap/dns.json` 仅 .com→`https://rdap.verisign.com/com/v1/`，避免额外IANA引导请求。真实443沿同一注册表访问公开 google.com 记录。
- 每个离线 WebSocket 请求均附小写/大写/嵌套代理覆盖字段，指向本地 decoy。SOCKS成功例 proxy=1、upstream=1、decoy=0；所有失败例 upstream=0、decoy=0。请求只能使用 config代理、无悄悄直连成功；不是只信 `viaProxy=true`。
- 真实链路：app 自己的 SOCKS5 → 本地raw TCP forwarder → `127.0.0.1:8791` HTTP CONNECT → `brd.superproxy.io:22228`。已读既有 `tcp_forwarder.py` 全文：只转发raw bytes，不解析/记录SOCKS认证或payload；仅计数accept/errors。新脚本未导入或运行旧 run_all/rerun，未运行其中.cn或旧head场景。
- 密钥文件0600，仅由脚本在内存解析；真实用户名/口令/完整代理URL从未输出、未放argv、未传子进程环境，只进0600临时config。密钥元数据PORT为44445（HTTP），因此最初守卫拒跑；后按本任务明确授权固定SOCKS22228，而非盲用HTTP端口。未探测替代出口或其他供应商端口。
- 正确凭据2例、错口令1例应用尝试；`RetryOnTimeout=false`；错口令无重试，避免锁账号。没有真正认证成功证据。
