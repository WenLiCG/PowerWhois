# PowerWhois 全项目审查与改进记录

日期：2026-11-03。原版基线：`bf1258b4dc7e067038cc6728f6868d4561fbfabb`，分支 `codex/review-ai-access`。审查覆盖后端入口、认证、配置、Redis、调度、DNS/WHOIS/RDAP、自定义接口、注册、Typo、前端状态/交互、依赖和部署材料。先记录 [最小改动方案](IMPLEMENTATION-PLAN.md)，再实施；沿用 Go/Fiber、Vue/Quasar、Redis，没有替换 Web 产品或另做四套查询逻辑。

## 已修复的主要问题

| 级别 | 原版问题及影响 | 修复位置与行为 |
|---|---|---|
| P1 | DNS 无 NS、传输失败曾被认为 Free，可能误导注册决策 | `lookup/lookuper` 统一五种状态；DNS 缺失为 unknown，失败为 error/timeout |
| P1 | RDAP 关闭 TLS 校验；删减隐私字段的正常域名对象被当作不存在 | `rdaplib` 保留证书验证，只把明确不存在响应映射为 not_found；有效匹配域名对象仍为 registered |
| P1 | 登录、WebSocket token、配置和第三方原始响应进入日志 | 删除秘密/原始载荷日志；JWT 从首帧认证，不放 WebSocket URL；查询 token 不能进入管理 API |
| P1 | 清空批量任务执行 FLUSHDB，可能连其他数据一起删除 | 新建任务只新增独立记录；兼容 clear 仅清 Web 当前选择/上传；没有数据库全清操作 |
| P1 | 结果保存失败仍移除待查域名；重启或重复启动可能漏查/重复计数 | Redis 持久化输入、稳定任务 ID、原子结果+计数提交、幂等键、单 worker 租约、恢复时跳过已提交结果 |
| P1 | Web 数量限制仅靠前端，线程数误用域名总数上限 | 服务端校验域名/数量/模式；Web 使用正确并发配置；协议级全局并发、每上游频率、超时及 Retry-After |
| P1 | 配置、连接表、limiter map 和取消操作存在并发问题 | 配置快照加锁、连接级串行控制、共享注册 limiter 加锁；上下文取消可中断网络与工作投递 |
| P1 | YAML 手工拼接、直接覆盖原文件，特殊字符或写失败可能毁配置 | 序列化、临时文件、Sync/替换；写成功才发布新配置；环境秘密不落盘 |
| P2 | 域名清洗静默移除非法字符；`foo.com.com` 会提取错误名称 | 入口严格校验/IDNA；后缀仅从末尾移除；静态后缀查询从线性扫描改为 map |
| P2 | RDAP/custom/WHOIS/注册响应体无有效上限；注册错误响应可能误判成功 | 查询与注册响应限制 2 MiB；HTTP 非 2xx 不能作为成功证据；注册不跟随重定向，不自动重试不确定交易 |
| P2 | 全局替换 `st/nd/rd/th` 破坏 August 等 WHOIS 日期 | 仅移除数字后的序数词后缀，增加真实格式回归测试 |
| P2 | 重复 WebSocket 消息让计数累加；断线后界面持续“处理中” | 同域名结果更新重算计数；断线标记未完成项，可重查；持久化批量任务不依赖连接 |
| P2 | 空后缀配置导致 Typo 页面 mounted hook 报错 | 共享设置 store 规范化空数组；后缀选择监听异步设置；浏览器复测通过 |
| P2 | 大表一次展示大量行、缺少状态筛选、缺少任务身份 | 即时查询表分页/筛选；批量页改为任务历史、稳定 ID、部分结果分页和取消确认；390px 窄屏验证 |
| P2 | 自定义 API 空标识/重名可能错误匹配，管理字段缺少后端边界 | 名称唯一、HTTP(S) URL、正反标识非空且不同；并发/时间/重试/认证参数均服务端校验 |
| P2 | CSV 可能把第三方字符串当作电子表格公式执行 | 对公式前缀及控制字符添加文字前缀；保留来源、查询时间和规范状态 |
| P2 | 默认部署直接对外映射且启用 profiling，旧预构建包与源码易混淆 | 源码构建容器、回环端口、profiling 默认关闭并要求管理认证；独立升级/回滚说明 |

新查询 API 与原管理 API 的权限分开。CLI/MCP 没有注册、清数据或修改配置工具。旧管理功能保留在 Web，手动注册增加服务端 `confirmed` 校验。token 过期/撤销后不继续推送兼容批量信息。

## 保留的限制与后续优化

1. **单租户、单活 worker**：批内并发，任务 FIFO；多份后端不能横向分摊同一队列。需要多用户/公平调度时再升级，当前不引入消息队列或微服务。
2. **持久化不等于无限容量**：任务、幂等键和原始结果长期保留；输入上限 100 万尚未做生产规模压测。启动恢复会读取任务历史；大量历史和大原始响应会增加内存、磁盘及恢复时间。没有自动删数据，以免越权或丢失记录。
3. **协议数据会漂移**：原静态后缀/WHOIS 匹配表保留。新 TLD、限流策略、注册局格式变化需要维护；未找到不能保证可注册。传统 WHOIS/DNS 本身不提供与 HTTPS RDAP 相同的传输真实性保证。
4. **Web 即时结果属于连接会话**：断线后可重查；需要恢复/跨入口同 ID 用批量任务。没有把每次临时查询都写入 Redis。
5. **导出有界**：API/CLI/MCP 一页最多 1000 条。Web 完整 CSV 最终在浏览器拼接，大规模导出建议用 API 分页写磁盘；不是百万行浏览器内存性能保证。
6. **依赖扫描**：生产 npm 依赖 0 项；完整 npm audit 仍有 12 个 moderate 条目，归于开发工具链的 minimatch 放大拒绝服务公告，不能写成“全仓零漏洞”。govulncheck 无受影响可达调用、无导入包级漏洞，仍提示 x/crypto 模块中未使用的 openpgp 公告。详见测试报告。
7. **接入条件**：本次验证了标准协议与本机 CLI，未实际绑定 ChatGPT dot、Grok 或用户 Codex 全局配置。HTTP MCP 尚无 OAuth，需按具体客户端使用受保护 Header 或另配合适的认证网关；没有为某个 AI 厂商硬编码业务。
